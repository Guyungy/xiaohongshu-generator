# 多人设多Agent流水线（面向 xiaohongshu-content-generator）

目标：固定人设风格（参考 persona 目录 SVG），批量生成「文案 + 3~6页 SVG 卡片」，并支持 marketing 审核打回返工。

## 角色
- main：统筹/任务单/合并打回/最终打包
- xhs-generator：按指定 persona 生成
- marketing-expert：增长审稿打回（P0/P1/P2，逐页定位）

## 强制约束
1. 必须显式指定 persona（不要依赖关键词路由）
2. 生成 SVG 前必须读取该 persona 目录中的 `*.svg` 作为风格基准
3. 禁止复用参考 SVG 的原文内容/具体数据
4. SVG 输出建议采用 `<defs><style>` token/class 结构（可维护）
5. 默认不要把页面做成 UI 面板拼贴；除非用户明确要求，否则优先采用“少分板块、强阅读流”的长图结构
6. 长文必须手动控制换行；不能依赖自动换行；文字绝不允许超出色块、安全区或容器边界
7. 当用户反馈“分块太多/像 PPT/像技术汇报”时，应直接减少小卡片、小标签、小信息盒，改为 1 个主标题 + 1~2 个大内容区的版式
8. 当发现“换行没问题但文字与色块匹配失控”时，不要继续打补丁，应直接重做页面版式约束
9. 流量优先的内容也必须保留真实性边界；禁止为了传播效果而做明显标题党或越过儿童/安全边界

## 输入契约（建议）
```yaml
persona: 驻校艺术家|张姐说国际教育|Mr Wong是码农|每日一校EduDaily|砂糖宝贝
topic: ...
brief: ...
refs:
  - url: ...
  - text: ...
output:
  pages: 3-6
  format: [svg, post_md]
  size: 1242x1656 # 可选
```

## 审核打回格式（marketing-expert）
- 总评分(1-10)+3句总评
- P0/P1/P2：逐页定位（第N页/卡片标题），并给“改成的具体文案/结构”
- 评论区引导：5条
- 风险：绝对化/引流/敏感

## 返工原则
- 一轮只改 P0
- 版本号：v1.0 → v1.1 → v2.0
