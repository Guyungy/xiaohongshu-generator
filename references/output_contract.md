# 输出约定（Output Contract）

适用于：`xiaohongshu-content-generator` 的标准交付结构。

## 必交付物

对于多页卡片任务，默认必须交付：

1. `01.png` ~ `0N.png`
2. `post.md`
3. 可选：对应源文件 `01.svg` ~ `0N.svg`
4. 可选：整包压缩文件 `topic_name.tar.gz`

---

## 画布标准

### PNG / SVG 卡片
- 默认画布：`1200 x 1600`
- 导出格式：PNG 为主，SVG 为可编辑源文件
- 字体：优先使用本机可稳定渲染的中文字体

### post.md
默认包含：
- 标题
- 正文（适合直接发小红书）
- 标签（建议 5-8 个，默认 8 个以内）

---

## 命名规范

### 目录
输出目录统一放在：

```text
output/<主题名>/
```

或在临时生成时：

```text
tmp/<主题名>/
```

### 文件命名
推荐：

```text
01.png
02.png
03.png
...
post.md
```

避免：
- `P1` / `P2`
- `第1页` / `Page1`
- 混乱的中英混合编号

用户明确要求不显示页码时，图片内容中也不得出现页码标识。

---

## 输出层级

### 标准成品层
```text
<topic>/
├── 01.png
├── 02.png
├── 03.png
├── 04.png
├── 05.png
├── 06.png
└── post.md
```

### 可编辑源文件层（可选保留）
```text
<topic>/
├── 01.svg
├── 02.svg
├── ...
```

### 打包层
```text
<topic>.tar.gz
```

---

## 内容结构要求

### 每张 PNG
必须包含：
- 明确的标题层级
- 统一品牌元素（若任务要求）
- 固定页脚（若任务要求）
- 可读的视觉重心

### post.md
推荐结构：

```md
标题：

正文：

#标签1 #标签2 #标签3 ...
```

---

## 交付完成定义（Definition of Done）

只有同时满足以下条件，才算真正完成：

- [ ] PNG 文件数量与页数一致
- [ ] `post.md` 已生成
- [ ] 命名符合规范
- [ ] 输出目录清晰
- [ ] 若要求群内交付，发送动作已完成
- [ ] 若发送失败，已执行 fallback，而不是停留在“本地已生成”
