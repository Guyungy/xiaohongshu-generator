# 输入约定（Input Schema）

适用于：`xiaohongshu-content-generator` 在生成 **小红书多页 PNG/SVG 卡片 + post.md** 时的标准输入。

## 最小输入

至少提供：

- `主题`：本次要表达的核心话题
- `人设`：例如 `Mr Wong是码农` / `张姐说国际教育`

若用户没有补全其余字段，允许根据上下文推断，但必须在执行时明确记录默认值。

---

```md
主题：
人设：
目标平台：小红书

交付方式：PNG / SVG / tar.gz / 发送到 Telegram
```

## 字段说明

### 1. 主题
- 一句话描述本次卡片的核心主张。
- 示例：`我儿子把 OpenClaw 装进了小天才手表`

### 2. 人设
- 决定文风、标题风格、视觉气质。
- 若用户未指定，但出现明显触发词，则自动路由到对应 persona。

### 3. 目标平台
- 默认：`小红书`
- 若同时要求群内交付，则仍以小红书内容形态产出，但交付渠道可为 Telegram。

### 4. 页数
- 默认 3 页。
- 对 `Mr Wong是码农` 连续卡片，通常为 2-6 页。
- 若用户要求整组输出，优先按 6 页规划。

### 5. 是否先出样稿
- 新主题默认：`是`
- 样稿最少 2 页：`封面 + 1 张正文页`
- 若用户明确要求“直接整组”，可跳过，但必须遵守产线规则。

### 6. 信息密度要求
- `低`：强调留白与单点表达
- `中`：每页 1 个主结论 + 2-3 个次信息
- `高`：每页要有主结论、补充判断、可执行动作或结构锚点，但禁止靠堆字实现

### 7. 视觉要求
用于记录用户的风格指令，例如：
- 不要过于工整
- 不要每页都一样
- 重点文字可以进块，其他文字尽量散开
- 增加箭头、状态、流程、注释等元素
- 信息密度再大一点，但不要乱
- 若上一版结构混乱，则下一版必须 re-design，不能只补字

### 8. 固定页脚
若用户指定固定页脚，必须逐页保留。

例：
`桐乡耀华STEM启发：方法先于答案｜过程可视化｜任务可执行`

### 9. 是否配套 post.md
- 默认：`是`
- 输出应包括标题、正文、互动钩子（可选）、8 个以内标签

### 10. 是否需要营销定稿
- 对高要求商业/转化内容，默认：`是`
- 先产出 marketing 定稿 JSON / 文案，再进入视觉渲染

### 11. 交付方式
可选：
- 本地目录输出
- `tar.gz` 打包
- 通过 Telegram 群/topic 发送

## 默认值（未说明时）

```yaml
目标平台: 小红书
页数: 6
是否先出样稿: 是
信息密度要求: 中高
是否配套 post.md: 是
是否需要营销定稿: 是
交付方式: 本地 + 可发送包
```

---

## 输入补全规则

当用户描述不完整时，按以下顺序补全：

1. 从当前会话上下文提取历史偏好
2. 从 persona 目录读取人设要求
3. 从 `PIPELINE_RULES.md` 读取硬规则
4. 将未说明项补默认值
5. 在执行时按内部计划记录，不必把所有默认值都回显给用户
